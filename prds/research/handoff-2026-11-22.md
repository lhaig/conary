# Conary Python 3 port: handoff (2026-11-22)

Notes from the earlier scratch port, kept as background for the norman tasks in ../TASKS.md.

## Goal

Revive Conary (Foresight Linux's package/system manager) as a working Python 3 client. Then decide
whether to build a new distro on it (Cinnamon desktop, Fedora or openSUSE base, RPMs encapsulated
into Conary).

## Repos

- Forks: https://github.com/lhaig/conary and https://github.com/lhaig/conary-policy
- Upstream: sassoftware/conary (Apache 2.0). Real code last changed in 2016 (2.5.9). rMake
  (sassoftware/rmake) is archived and unsupported.
- Foresight Linux shut down in May 2015. Last release 2.5.3 (2013).

## State of the code (measured)

- About 140k lines of Python across 258 files, plus about 15k lines of C.
- On Python 3.13, 147 files failed to compile. After a mechanical 2to3 run (from Python 3.11),
  only 2 failed: `conary/lib/magic.py` (tab/space mix, line 300) and `conary/pysqlite3/setup.py`
  (legacy string raise).
- The C layer already has a Py2/Py3 compatibility header (`conary/lib/pycompat.h`).

## Scratch-port steps

1. `python3.11 -W ignore -m lib2to3 -w -n -j4 conary conary_test commands scripts`.
2. Generate `conary/constants.py` from `constants.py.in` (`@version@` -> 2.5.9, `@changeset@` -> any string).
3. `conary/lib/epdb_embedded/__init__.py`: `from pdb import _saferepr` -> `from reprlib import repr as _saferepr`.
4. In `conary/lib/ext/{dep_freeze,digest_uncompress,pack,streams}.c`, `#include <Python.h>` before
   `#include "pycompat.h"`, otherwise the module macro takes the Python 2 branch.
5. Regenerate Cython output with a current Cython for file_utils, sha256_nonstandard and system.
6. In `common.pxi`, `sha256_nonstandard.pyx`, `file_utils.pyx`: `PyString_*` -> `PyBytes_*`.
7. Build each extension with `-I conary/lib`; `-lcrypto -lz` for digest_uncompress;
   `helper_sha256_nonstandard.c` for sha256_nonstandard. All 7 compiled for Python 3.11.

## Blockers at handoff

1. `file_utils` calls `PyFile_FromFile`, removed in Python 3.
2. `conary/pysqlite3` (about 1,800 lines of Python 2 C API) should be replaced with stdlib `sqlite3`.
3. Then expect string/bytes problems that 2to3 does not fix: hashes, binary changesets, the
   database, file contents. Audit I/O boundaries and the stream/changeset code.

## Not yet tested

`import conary`, `conary_test`, repository server, `conary-policy`, rMake/rBuild replacements, RPM
encapsulation (Conary 2.2 feature, unproven), bootstrapping a base from Fedora or openSUSE.

## Suggested plan

1. Fix the blockers until `import conary` and `conary --version` work.
2. Run `conary_test` and triage failures, bytes/str first.
3. Install, query and rollback against a local test repository.
4. Prove or disprove RPM encapsulation with a small Fedora or openSUSE subset.
5. Decide on the build side (rMake replacement) and hosting, then the distro question.
